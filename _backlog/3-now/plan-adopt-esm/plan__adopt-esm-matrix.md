## Recipe

Piloted on `art-md/libs/codec` (Node consumers `cli/bin` and `cli/codec-tests`; smallest tested public surface; its suite exercises `createArtCodec`). Replay it once per row group, one commit per checkout. `{checkout}` and `{package}` come from the matrix.

1. Setup the checkout — `cd $CHECKOUTS/{checkout} && npm ci && (git switch adopt-esm || git switch -c adopt-esm)` — expected: a clean tree; never discard pre-existing uncommitted rows belonging to another batch.
2. Authorised dependency bump — `npm install @noodlestan/tsconfig@^0.2.0 @noodlestan/esbuild@^0.1.0` (checkout root) — expected failure mode: the pre-`0.2.0` pin ships no `esbuild/` preset and no `esbuild-cli`, so step 3 fails with `Cannot find module '@noodlestan/tsconfig/esbuild/tsconfig.json'`; the install rewrites `package.json` and `package-lock.json` and rides along in the same commit. Run it even when the root already pins `0.2.0`/`0.1.0` — the ranges are then the only diff.
3. Preset flip — in `{package}/tsconfig.json` set `"extends": "@noodlestan/tsconfig/esbuild/tsconfig.json"`, keeping the package's `include` and `exclude` — expected failure mode: none at this step; the breakage surfaces in step 7 when `module`/`moduleResolution` become `NodeNext`.
4. Build scripts — in `{package}/package.json` set `"dev": "esbuild-cli-watch"` and `"build": "esbuild-cli"`, keep `"build:clean": "rm -rf dist"`, and confirm `"type": "module"` (all 11 rows already declare it — never add a second one) — expected failure mode: `esbuild-cli` is not on `PATH` until step 2 installed `@noodlestan/esbuild`.
5. Consumer-owned build config — create `{package}/build.config.mjs` on the `common` / `esm` shape: `bundle: true`, `tsconfig: 'tsconfig.build.json'`, `entryPoints: ['src/index.ts']`, `external` = the package's direct non-workspace `dependencies` (`[]` when it has none), `define: { __BUILD_VERSION__: JSON.stringify(version) }` read from `package.json`, and `esm.plugins: [postBuildPlugin({ command: 'tsc', args: ['--project', 'tsconfig.types.json'], target: 'esm' })]` — expected failure mode: workspace dependencies (`@noodlestan/*` siblings with `main: ./src/index.ts`) must stay **out** of `external`, because `node dist/index.mjs` cannot load a `.ts` entry (and their `./x.js` specifiers do not exist on disk); bundle them, as `art-md/cli/bin` does. Only real npm runtime packages (`commander`, `mdast-*`, `unist-*`, …) are external.
6. Declaration emit configs — create `{package}/tsconfig.build.json` (`extends: "./tsconfig.json"`, `rootDir: "src/"`, `outDir: "dist/"`, `include: ["src/"]`) and `{package}/tsconfig.types.json` (`extends: "./tsconfig.build.json"`, `emitDeclarationOnly: true`, `include: ["src/"]`) — expected failure mode: without them the build fails on `tsconfig: 'tsconfig.build.json'` and the `postBuildPlugin` produces no `.d.ts` in `dist/`.
7. Type-check — `cd $CHECKOUTS/{checkout} && npx tsc -p {package}/tsconfig.json --noEmit` — expected failure modes and resolutions:
   - `TS2834` / `TS2835` relative import paths need explicit extensions → append `.js`; an extensionless directory import becomes `…/index.js`.
   - `TS2307` on a deep package subpath (`@art-md/primitives/src/test/helpers`) → resolve it to `…/helpers/index.js`; NodeNext has neither directory nor extensionless package-subpath resolution.
   - `verbatimModuleSyntax` import-shape errors → `import type …`.
   - `TS2305` "has no exported member" coming from a published sibling artifact → the sibling's re-export chain collapses under `NodeNext`; not repairable from this checkout (escalate, see the iteration report).
8. Drop the orphaned Vite build config — `git rm {package}/vite.config.ts {package}/tsconfig.vite.json` — expected failure mode: leaving them keeps a `libs/` `extends` inside a migrated package (`tsconfig.vite.json`) and a dead `dist/esm/` target referenced by `vite.config.ts`. Keep `vitest.config.ts`.
9. Verify the package — from `{package}`: `npm run lint && npm run test && npm run build` — expected: all exit 0.
10. Verify the checkout — from the checkout root: `npm run ci` (root `prettier . -c` plus `turbo run ci`; the checkout root has no `test`/`build` scripts, so this is the runnable form of the instruction's verifying step) — expected: green; the same command runs on the pre-commit hook after `clean` and `extract`.
11. Prove the output — `ls {package}/dist` shows `index.mjs` beside `*.d.ts`, and `node {package}/dist/index.mjs` exits `0` without a loader flag — expected failure mode: a stale `dist/esm/` left by the Vite build; run `npm run build:clean` first (the hook's `clean` step does it for you).
12. Commit — stage every file changed for the checkout's rows plus the step 2 dependency bump, commit with the iteration blueprint message, and do **not** push (`NOPUSH`); then set the rows to `DONE` in this matrix (that edit stays uncommitted for the planner).
